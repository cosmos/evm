# Cosmos EVM v0.7.x -> v0.8.0 Migration

v0.8.0 removes the deprecated `contrib/x/precisebank` module and standardizes on 18-decimal EVM gas-token configurations.

## Key change

- `contrib/x/precisebank` is no longer shipped in this repository.
- Non-18-decimal gas-token chains are not supported in v0.8.0.

## Required actions

1. Remove all `contrib/x/precisebank` imports from your app and tests.
2. Remove precisebank keeper/module wiring from app construction:
   - `PreciseBankKeeper` fields/getters
   - `precisebank.NewKeeper(...)`
   - `precisebank.NewAppModule(...)`
   - begin/end/init module ordering entries for precisebank
3. Replace call sites that previously relied on precisebank translation with native 18-decimal flows.
4. Ensure your EVM coin config uses 18 decimals (`EvmCoinInfo.Decimals = 18`).

## Operator guidance

- If your chain still depends on non-18-decimal behavior, do not upgrade to v0.8.0 yet.
- Migrate token denomination/decimals strategy first, then upgrade.

## Cosmos SDK v0.55 and CometBFT v0.40

v0.8.0 builds on Cosmos SDK `v0.55.0`, CometBFT `v0.40.0` and IAVL `v1.2.9`. The full SDK changes are in the [SDK v0.55 upgrade guide](https://github.com/cosmos/cosmos-sdk/blob/release/v0.55.x/UPGRADING.md); the steps below cover what an EVM chain built on `evmd` needs.

### Dependencies

1. Bump `github.com/cosmos/cosmos-sdk` to `v0.55.0` and `github.com/cometbft/cometbft` to `v0.40.0`.
2. Replace `github.com/cosmos/ibc-go/v11` with `github.com/lfdt-ibc/ibc-go/v11` in `go.mod` and in every import. ibc-go moved to LFDT; the module path changed, the packages did not:

   ```bash
   grep -rl 'github.com/cosmos/ibc-go/v11' --include='*.go' . \
     | xargs sed -i 's#github.com/cosmos/ibc-go/v11#github.com/lfdt-ibc/ibc-go/v11#g'
   ```

### App wiring

1. Drop the trailing legacy-subspace argument from `auth`, `bank`, `gov`, `mint`, `slashing`, `distr` and `staking` `NewAppModule` calls (`x/params` is removed).
2. Add the key rotation fee pool to the module account permissions:

   ```go
   stakingtypes.KeyRotationFeePoolName: {authtypes.Burner},
   ```

3. Remove `SIGN_MODE_TEXTUAL` wiring: the `EnabledSignModes`/`TextualCoinMetadataQueryFn` tx config override in `app.go`, and the online-mode tx config override in the root command.
4. Replace `genutil.ExportGenesisFileWithTime(genFile, chainID, nil, appState, genTime)` by setting `GenesisTime` and `AppState` on the loaded `AppGenesis` and calling `genutil.ExportGenesisFile`.

### Genesis

Set the staking `key_rotation_fee` denom to the bond denom in any new genesis file. The SDK defaults it to `stake`, and genesis validation fails with `key rotation fee denom "stake" must match bond denom` otherwise:

```bash
jq '.app_state.staking.params.key_rotation_fee.denom = .app_state.staking.params.bond_denom' genesis.json > tmp.json && mv tmp.json genesis.json
```

Existing chains do not need this: the `x/staking` 5 to 6 store migration sets the fee in the bond denom.

### Upgrade handler

`RunMigrations` runs the `x/staking` 5 to 6 and `x/auth` 6 to 7 migrations. No store keys are added. If the app still mounts the `protocolpool` or `params` store, list it under `Deleted` in the upgrade's `StoreUpgrades`.

### Custom mempools

Chains that use the EVM mempool need no changes. Code that calls the mempool directly must pass a `mempool.InsertOption` to `Insert`, read `PooledTx.Tx` from `Iterator.Tx()`, and take a `func(mempool.PooledTx) bool` in `SelectBy`.
