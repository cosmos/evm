# Cosmos EVM v0.7.x -> v0.8.0 Migration

v0.8.0 removes the deprecated `contrib/x/precisebank` module and standardizes on 18-decimal EVM gas-token configurations.

## Key change

- `contrib/x/precisebank` is no longer shipped in this repository.
- Non-18-decimal gas-token chains are not supported in v0.8.0.

## Required actions

1. Remove all `contrib/x/precisebank` imports from your app and tests.
2. Remove precisebank keeper/module wiring from app construction:
   - `PreciseBankKeeper` fields/getters
   - `precisebank.NewKeeper(...)`
   - `precisebank.NewAppModule(...)`
   - begin/end/init module ordering entries for precisebank
3. Replace call sites that previously relied on precisebank translation with native 18-decimal flows.
4. Ensure your EVM coin config uses 18 decimals (`EvmCoinInfo.Decimals = 18`).

## Operator guidance

- If your chain still depends on non-18-decimal behavior, do not upgrade to v0.8.0 yet.
- Migrate token denomination/decimals strategy first, then upgrade.

## EIP-2935 history serve window

The preinstalled history storage contract (`0x0000F90827F1C53a10cb7A02335B175320002935`) reads block hashes from slot `number % 8191`, but the chain stored them at `number % history_serve_window`, which defaulted to 8192. From height 8191 on, the contract's `get(n)` returned the hash of another block (or zero), while `BLOCKHASH` stayed correct.

- The default `history_serve_window` in new genesis files is now 8191.
- `history_serve_window` must not exceed 8192. A chain with a larger value has to lower it the next time it updates the `x/vm` params.
- An unset window (`0`) still means 8192, so upgrading the binary does not move any stored hash. No store migration is needed.
- When `MsgUpdateParams` changes the window, the hashes of the last `min(old, new)` blocks are moved to their new slots and the other slots are cleared. This runs once, in the block where the proposal executes, and touches at most 8192 slots.

### Required actions

None for the upgrade itself. To make the history storage contract return the right hashes, submit a governance proposal with `MsgUpdateParams` that keeps the current `x/vm` params and sets `history_serve_window` to `8191`. Chains that do not use the contract can keep their current window.
